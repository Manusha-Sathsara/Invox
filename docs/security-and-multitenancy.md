# Security & Multi-Tenancy Architecture

## 1. Zero-Trust Multi-Tenancy Model

### Anti-Patterns Prevented
- **No Client-Side Tenant Passing (IDOR Prevention):** Clients never pass `tenantId` in URLs or body parameters. Tenant identity is strictly derived from the verified `X-JWT-Assertion` generated by WSO2 APIM.
- **No Client-Side SCIM Scopes:** Public frontend clients only request presentation scopes. Administrative operations are performed by Spring Boot via M2M Client Credentials.
- **Gateway Multi-Tenancy Handling:** Unified API deployment within Carbon Super Tenant; multi-tenancy is enforced dynamically through token claims and database isolation.

---

## 2. Spring Boot Request Ingress Lifecycle

1. Request enters Spring Boot servlet filter (`ApimJwtAssertionFilter`).
2. Intercepts and parses `X-JWT-Assertion` header.
3. Extracts `tenant_id` (or `groups`) and assigned `roles`.
4. Injects `UsernamePasswordAuthenticationToken` into `SecurityContextHolder`.
5. Sets `TenantContext.setCurrentTenant(tenantId)`.
6. Enforces `try-finally` lifecycle cleanup:
   ```java
   try {
       filterChain.doFilter(request, response);
   } finally {
       TenantContext.clear();
       SecurityContextHolder.clearContext();
   }
   ```

---

## 3. Database Isolation via Hibernate 6 `@TenantId`

- Implementation of `CurrentTenantIdentifierResolver<String>` bridging Hibernate to `TenantContext.getCurrentTenant()`.
- Entity definitions include:
  ```java
  @TenantId
  @Column(name = "tenant_id", nullable = false, updatable = false)
  private String tenantId;
  ```
- Hibernate automatically appends `WHERE tenant_id = ?` to all select/update/delete operations and populates `tenant_id` on inserts.
